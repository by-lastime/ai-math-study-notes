# 补充问答维护

每讲一个 Markdown 档案，文件名以两位讲次开头，例如 `03-条件概率.md`。新问题按本讲顺序编号，不重编号已有条目。

讲解优先从具体情景和普通话开始，再引入必要的符号及术语；保留关键步骤，但不要为了完整而堆叠专业词语或套用冗长模板。用户要求简化已有讲解时，可把简明版本放在前面，将原详细推导折叠保留，避免首次阅读负担。

格式：

```markdown
## Q003：问题标题

**用户追问**（仅在确有该追问时使用；预置内容用“讲解补充”）

准确的问题及完整解释，可使用 KaTeX 数学公式。
```

正文链接格式：`[Q003：问题标题](qa:03/Q003)`。只有实际存在的问答才能加入链接，构建会校验；同一讲不能出现重号。不同讲可各有 Q001。

网页讲义正文只保留对应位置的问答链接，点击后在疑问弹窗中阅读完整内容。用户提问及完整解答保存在本目录的问答档案里，不要再将问答全文、教学例子或“常见疑问”展开块自动插入讲义正文；构建及纸电同步也应遵守这一显示规则。已有课程正文和来源题解析继续保留。

在本地服务模式下保存文件会自动重新构建；阅读器每隔数秒检查内容版本。弹窗或输入框正在使用时延后更新，避免打断；关闭弹窗或结束输入后继续更新。失败构建保留上次成功内容并显示错误提示。

离线 `index.html` 支持问答弹窗，但不监听文件修改；先运行 `node 电子讲义/阅读器/build.mjs`，再刷新页面。

网页本身不调用外部 AI、不自动回答新问题。后续在对话里提问，由助手将已完成的解答写入本讲档案并链接回正文。原文与问答留在本机。
